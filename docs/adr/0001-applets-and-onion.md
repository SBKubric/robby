# Апплеты как единица расширения, Onion-архитектура в двух модулях

Robby должен расширяться без правок движка и редактора, поэтому всё, что сценарий умеет — триггеры, условия и действия, — предоставляют **апплеты**, реализующие один общий контракт; редактор и движок знают только этот контракт и каталог апплетов. Коннектор (Telegram) — это апплет, которому нужна учётная запись внешнего сервиса. Код устроен по Onion: в центре чистый Kotlin (домен: Сценарий, Срабатывание, Журнал, правила движка, контракт апплета; прикладной слой: use cases и порты), снаружи адаптеры Android, Room, HTTP и UI; зависимости направлены только внутрь.

## Considered Options

- **Апплеты-плагины отдельными APK во время работы** — отклонено (KISS): IPC, безопасность и версионирование ради функции, которая одному владельцу не нужна. Апплеты встроены в APK и регистрируются в каталоге одной строкой.
- **Модуль Gradle на каждый апплет и слой** — отложено (KISS): на старте только `:core` (чистый Kotlin/JVM: домен, use cases, порты, контракт апплета) и `:app` (Android: адаптеры, реализации апплетов по пакетам, UI, сборка зависимостей). Граница `:core` → без Android держит Onion средствами компилятора; дробить дальше — когда станет тесно.
- **Фиксированный набор условий в движке** (как в первой версии модели сценария) — заменено: условия тоже приходят из апплетов.

## Consequences

- Движок и use cases тестируются на JVM без эмулятора.
- Android-часть апплета (ресивер, сервис, HTTP) живёт в `:app` и общается с `:core` только через порты.
