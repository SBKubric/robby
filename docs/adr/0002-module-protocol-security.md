# Защита связи Robby ↔ внешний модуль: своё HMAC-рукопожатие и AES-GCM, а не TLS

Команды (TCP) и звук звонка (UDP) между Robby и внешним модулем идут по домашнему Wi-Fi и шифруются: при каждом TCP-подключении стороны доказывают знание общего ключа модуля рукопожатием на HMAC-SHA256 со случайными числами обеих сторон, выводят ключ сессии через HKDF-SHA256 и шифруют каждое сообщение и каждый кадр звука AES-128-GCM (nonce — счётчик направления или номер сессии + порядковый номер кадра). Ключ модуля Robby генерирует заново при каждой настройке по Bluetooth; модуль держит его только в оперативной памяти; сам канал настройки защищён шифрованием Bluetooth после сопряжения.

## Considered Options

- **TLS-PSK** — отклонено: на Android нет штатной поддержки PSK-шифров (только через скрытый Conscrypt), а для звука по UDP понадобился бы ещё и DTLS.
- **TLS с сертификатами** — отклонено: выпуск и закрепление сертификатов для одного модуля в одной квартире сложнее, чем задача.
- **Без шифрования в домашней сети** — отклонено владельцем: звук звонков и команды «ответить» должны быть закрыты и от устройств в той же сети.
- **Постоянный ключ** — отклонено: новый ключ при каждой настройке бесплатен (настройка и так повторяется при каждом подключении гарнитуры) и не оставляет секрета в модуле.

## Consequences

- AES-GCM на ESP32 считается аппаратно; на Android — `javax.crypto` без зависимостей.
- Версия протокола в `hello`: несовпадение — отказ работать с подсказкой обновить прошивку или Robby.
